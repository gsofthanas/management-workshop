HOOK / まず一度、見る

「作って」で物が生まれる

講師が実際に『単一HTMLのツールを作って』と頼む。Codexが差分(diff)を見せ、y/nで承認すると、ファイルが生まれてすぐ動く。

見るポイント
注目するのは『差分が出て y/n を押す瞬間』。これがCodexの正体。

強力だからこそ、今日はまず"安全に持つ"を学ぶ

BASICS / Codexとは

チャットの"次"

01
話す（LLM・チャット）
ChatGPTの画面で会話する
02
コードから呼ぶ（API）
プログラムが入力を送る（前回）
03
操作する（Codex）
AIがファイルを読み・書き・コマンドを実行する

Codexは4つの入口（CLI・IDE・クラウド・アプリ）から使える1人のAIエンジニア。同じChatGPTでログイン。既定モデルはGPT-5.5。

きょう触るのはCLI（ターミナル）。デスクトップ"アプリ"とは別物

MINDSET / なぜ"心構え"が先か

速く強い＝間違いも速い

Codexは数百回の操作を自分で連鎖できる。便利な反面、間違いも一気に進む。だから先に安全のしくみを知る。

01
存在しないライブラリを"それらしく"作る
捏造。実在を確認する
02
頼んでいないファイルまで編集する
差分を必ず読む
03
差分を盲信する
テスト・レビューは人間が持つ

次から、安全の"2つのつまみ"を手で確かめる

SAFETY / 安全の2層

壁とチャイム

壁 / サンドボックス

AIが"何を触れるか"

Read Only（読むだけ）／ Auto（フォルダ内で書ける）／ Full（無制限・使わない）

チャイム / 承認

AIが"いつ確認するか"

書く前に差分を見せて y/n。承認するまで適用しない

既定の設定
フォルダ内は書ける・外部とネットは既定オフ。だから安全に試せる。

一番安全な読むだけ

安心ポイント
書き込まないモードだから、安心して何でも聞ける。
APPLY / 差分 → 承認 → 適用

勝手に書かない。diffを見て y/n

Codexは変更を差分(diff)で見せて y/n を待つ。承認して初めてファイルになる。/approvals で Auto にすると、安全な範囲は自動で進む。

>codex wants to apply a change to report.html
>+ <html> … 売上レポート …
>Apply this change? [y/n]

/diff で現在の差分・/review で変更をレビュー
