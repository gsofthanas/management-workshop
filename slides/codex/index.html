HOOK / まず一度、見る

「作って」で物が生まれる

講師が実際に『単一HTMLのツールを作って』と頼む。Codexが変更をReviewペインに差分で並べ、採用するとファイルが生まれてすぐ動く。

見るポイント
注目するのは『差分が並んで“採用”を押す瞬間』。これがCodexの正体。
BASICS / Codexとは

チャットの"次"

01
話す（LLM・チャット）
ChatGPTの画面で会話する
02
コードから呼ぶ（API）
プログラムが入力を送る（前回）
03
操作する（Codex）
AIがファイルを読み・書き・コマンドを実行する

Codexは4つの入口（CLI・IDE・クラウド・アプリ）から使える1人のAIエンジニア。同じChatGPTでログイン、既定モデルはGPT-5.5。近縁の"操作するAI"に Claude Code（計画力・巨大コンテキストが持ち味）。

SAFETY / 安全の2層

壁とチャイム

Codexは操作を自分で連鎖でき、速い反面間違いも一気に進む（捏造・勝手な編集・差分の盲信）。だから先に安全の2層を持つ。

壁 / サンドボックス

AIが"何を触れるか"

既定でフォルダ内は読み書きOK。フォルダ外・ネット・危険な操作は止まって"要承認"になる

チャイム / 承認

その"要承認"を誰が出す？

承認を求める＝あなたが1つずつOK ／ 代理で承認＝自動レビューが代行（リスク度つき・速い）

今日の選び方
今日は 承認を求める。フルアクセス＝壁なし・使わない／カスタム＝細かく指定・上級。

PRACTICE / 02 / まず1回動かす（codextest）/ 5 MIN

空フォルダで肩慣らし

本番の前に、承認モードは 承認を求める で 作る→書く→見る→開き直す を1回通す。

01
フォルダを作らせる
チャット欄に『C:\Users\自分\codextest を作って』
02
メモを書かせる
『codextest に test.txt を作り「このフォルダは Codex の動作テスト用」と書いて』
03
中身を表示させる
『test.txt を表示して』→ アプリで確認
04
開き直す
新しいセッションで codextest を開く → ここから本番
安心ポイント
承認が出たら中身を見てOK。作る・書く・見るの手触りをつかむ。
APPLY / 差分 → 採用 → commit

勝手に確定しない。Reviewペインで差分を見る

変更はReviewペインに Git 差分で並ぶ。チャンク単位で採用（stage）/取り消し（revert）でき、納得したら commit。代理で承認なら安全な範囲は自動で進む。

>report.html — changed (Git diff)
>+ <html> … 売上レポート …
>revert chunk / stage chunk → commit
PRACTICE / 03 / 売上Excelを作る・集計 / 9 MIN

売上.xlsxを生成→集計

01
売上データを作る

読んで集計する

進め方
承認を求めるで1つずつOK（差分を読んでから）。速くしたいなら 代理で承認。
