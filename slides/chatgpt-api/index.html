BASICS / Web API とは

APIは別サービスへの注文口

Web API は、画面を人が操作する代わりに、プログラムがHTTPで依頼を送り、結果を受け取る仕組み。

CLIENT

自分のコード

アプリ・HTML・サーバーなど、呼び出す側。

→
REQUEST

HTTPリクエスト

URL・キー・注文内容をまとめて送る。

→
RESPONSE

結果が返る

JSONなどのデータを受け取り、画面や処理に使う。

BASICS / LLM API とは

チャット欄と
コードの違い

ChatGPT の画面は人間が会話する場所。LLM API は、プログラムが入力・指示・設定を送る入口。 返ってきた文章を、自分のアプリで自由に使える。

今日はこの入口を配布HTMLから直接叩く

CHAT UI
人 人が入力 画面で会話する
→
返 返事を読む その場で使う
LLM API
{} コードが送信 入力・指示・設定
→
JS 結果を使う 自分のアプリへ
LLM API / 4つの特徴

LLM APIの4つの特徴

01
プログラムから呼ぶ
fetch で HTTP リクエストを送る
02
今日の方式は毎回まっさら
この教材では履歴を自分で渡す。状態管理は応用編
03
従量課金
使ったトークン分だけ料金がかかる
04
instructions（共通指示）を自分で握れる
AIの役割・口調を固定できる

Responses API には previous_response_id / conversation もある。今日は手で履歴を渡す方式

WARNING / APIキーの取り扱い

APIキーは
「鍵」かつ「請求書」

キーを持つ誰でも、あなたの口座でAIを呼べる。流出＝そのまま請求になる。

❌ 絶対NG
ソースコードに直書き
Git にコミット
Slack・メールで共有
公開ページのJSに埋め込む
✅ 正しい扱い方
研修用ツールの入力欄から設定
本番はサーバー側で管理
この場ではブラウザ内だけ（BYOK）
1人1キーを守る
研修後はキーをクリア
流出に気づいたら即無効化

今日のツールは研修用。本番ではブラウザJSに置かず、サーバーの環境変数や鍵管理から呼ぶ

READ / リクエストの中身

送っているのはこの“注文書”

コードの中の body が、AIへの注文書。ここを書き換えるのが今日の操作の中心。

>model=使うAIモデル
>instructions=共通ルール（口調・役割）
>input=ユーザーの発言（会話の中身）
>temperature=返事のばらつき（0〜2）
>max_output_tokens=出力全体の上限（reasoning含む）
>text.verbosity=返事の詳しさ
TOKENS / 料金の単位

料金はトークンで決まる

トークンは、文章をAIが扱うための細かい単位。入力と出力で別々に数え、モデルごとに単価が違う。

INSTRUCTIONS / 共通プロンプト

固定ルール ×
毎回の入力

instructions は毎回必ず効く“共通ルール”。口調や役割をここで固定し、 ユーザーの入力（input）だけを変える。これが実アプリの形。

同じルールを固定すると、アプリの振る舞いが安定する

PRACTICE / 03 / 共通プロンプト / 4 MIN

instructions で別人にする

見るポイント：口調・形式・箇条書き数。
PARAMETERS / 触って分かる3つ

返事を調整する3つ

01
temperature
ばらつき。0＝毎回ほぼ同じ、高い＝暴れる
02
max_output_tokens
出力全体の上限。reasoning分も含む。小さいと切れる
03
text.verbosity
詳しさ。low＝簡潔 / high＝詳しめ

top_p は温度の親戚（今日は触らずでOK）。reasoning.effort は応用編
